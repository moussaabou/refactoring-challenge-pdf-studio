# 🧹 تحدي إعادة الهيكلة: PDF Studio

لديك تطبيق ويب **يعمل**، لكن كوده فوضوي. مهمتك أن تجعله **نظيفاً وقابلاً للتطوير** دون أن يتغير سلوكه.

## ما هو التطبيق؟
ست أدوات PDF تعمل من المتصفح: صور إلى PDF، PDF إلى صور، حذف صفحات، إضافة صفحة، دمج ملفات، تدوير واستخراج.

```
├── index.html
├── style.css
└── script.js   ← التحدي هنا
```

## قواعد التحدي
1. **لا تغيّر السلوك**: كل الأدوات الست يجب أن تعمل كما كانت.
2. يمكنك تعديل الملفات الثلاثة، لكن يُمنع إضافة مكتبات جديدة غير الثلاث الموجودة.
3. يُسمح بتقسيم `script.js` إلى عدة ملفات (ES Modules) إذا أردت.
4. يُمنع استخدام الذكاء الاصطناعي لكتابة الحل كاملاً (استخدمه للتعلم فقط).

## المطلوب
- [ ] تقسيم الدالة الضخمة `go()` إلى وحدات مستقلة لكل أداة.
- [ ] فصل المنطق عن الواجهة (DOM).
- [ ] إزالة التكرار (يوجد دالتان متشابهتان للتحميل، وأخريان لتحليل أرقام الصفحات).
- [ ] تسمية واضحة للمتغيرات والدوال، وإزالة الكود الميت.
- [ ] توحيد معالجة الأخطاء والتحقق من المدخلات.
- [ ] **إيجاد 6 أخطاء خفية** وإصلاحها (اذكرها في وصف الـ Pull Request).
- [ ] **اختبار المرونة:** أضف أداة "عكس ترتيب الصفحات" بأقل من 10 أسطر JS.

## كيف تشارك؟
1. اعمل **Fork** لهذا المستودع.
2. أنشئ فرعاً باسمك: `git checkout -b solution-اسمك`
3. نفّذ التعديلات واعمل **Commits** صغيرة بعناوين واضحة (تُحسب ضمن التقييم).
4. افتح **Pull Request** وفي وصفه:
   - ماذا غيّرت ولماذا؟
   - الأخطاء الستة التي وجدتها.
   - ما الذي ستحسّنه لو توفر لك وقت أكثر؟
